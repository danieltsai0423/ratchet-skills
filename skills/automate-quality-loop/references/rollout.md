# 分階段導入與試跑

| 階段 | 設定 | 放行證據 |
| --- | --- | --- |
| 事件觸發後報告 | 固定發版版本與測試夾具，在隔離環境執行。告警、工單或訊息觸發時，記錄來源事件並對應到版本。記錄結果、執行耗時、版本與重跑資訊。測試帳號和工作身分只需目前階段的權限。 | 成功、可重現的測試失敗與環境故障各有可辨識的輸出。重疊排程受限，同一版本的重複事件不重複開案。 |
| 修復分支與草稿 PR | 對可重現的產品失敗使用穩定識別，例如失敗性質與正規化的原因特徵。失敗已存在時附加新證據或更新同一修復分支。 | 同一輸入重播、修復後通過、必要 CI 檢查結果，且每個已追蹤問題至多有一個進行中的修復。 |
| 合併 | 僅在專案允許且已有相應授權的範圍，評估平台內建 auto-merge。沿用受保護分支的必要檢查與審查，並在目標分支更新後重新評估合併條件。 | 已演練停用與回復，已定義允許的變更範圍。資料遷移、權限調整等高風險變更走專案既有的審查流程。 |

上線前手動試跑一個通過案例、一個可穩定重現的失敗及一個環境故障，再重送同一事件驗證去重。從小範圍開始，以可重現失敗比例、誤報、修復撤銷、整體回退率、跨版本效能基準與執行成本作為擴大依據。若必要驗證逾時或失效，暫停自動寫入，保留已產生的執行證據並交由維護者處理。
