# 導入外迴圈品質自動化

外迴圈在事件觸發後重跑產品品質驗證，將可重現的失敗交回開發與審查流程。觸發來源可以是排程、發版、監控或錯誤追蹤告警、新工單、團隊訊息或使用者回饋。內迴圈仍會產出需要大量人工修正的結果時，先改善內迴圈，自動化只會放大它的產出。

1. 找出適合試行的產品流程與觸發來源。來自告警、工單或訊息的事件，先轉成固定版本與可重現步驟再進入流程，無法重現的保留為待確認報告。先確認本地或 CI 能固定待測版本與初始狀態、重現失敗、執行必要檢查並留下證據。若條件不足，先在內迴圈補齊缺口，或把排程限定為收集測試結果。
2. 用隔離環境與合成資料重跑固定案例。探索組合時用有界的屬性或隨機測試，保留 seed、可重跑輸入或操作序列。設定逾時、重試上限與執行預算。把測試失敗、環境故障和不穩定結果分開記錄，對同一失敗合併回報。發版後的探索測試以同一組案例重跑上一個穩定版，將發現分為本版新增與既有問題，新增問題依嚴重度優先處理。
3. 先以唯讀報告驗證流程。經授權才把可重現的產品失敗升級為修復分支或草稿 PR。PR 應附重現前後結果、針對性回歸驗證與既有必要檢查，並依專案規則交審。合併或部署遵守專案政策與本次授權。
4. 提高自動化範圍前，確認可追溯版本、有負責人與可操作的暫停方式。回報啟用階段、試行結果、各階段的放行證據與停用方式。

需要設計排程、草稿 PR 或受保護的合併流程時，讀 [分階段導入與試跑](references/rollout.md)。
