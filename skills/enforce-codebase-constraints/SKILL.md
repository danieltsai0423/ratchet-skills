# 建立程式碼庫約束

Agent 會把程式碼庫裡的既有寫法當成範本，每多一份權宜寫法，下一次被複製的機率就更高。每次糾正 Agent，都以一項確定性檢查或一次架構修正收尾，讓同類錯誤不必在審查中再抓一次。

1. 從剛做的糾正、實際失敗、審查紀錄或違規實例找出共同模式。定義違規條件、合法用法和適用範圍。確認直接呼叫者、現有替代做法及必要例外，挑一個能代表正確路徑的專案範例。
2. 先檢查能否透過公開介面、模組可見性、型別或明確目錄邊界整類消除錯誤路徑。需要細膩判斷才能用對的 API，優先收進封裝，只在封裝內部允許使用。目錄以功能或執行環境命名，讓位置本身說明能力與邊界。仍可誤用時，沿用專案既有的靜態工具。依判斷需要選 import 檢查、語法樹或依賴圖，並讓檢查涵蓋實際使用的別名或重新匯出。只適合在執行期辨識的情況交由行為測試。
3. 將檢查接到專案平常使用的 lint、型別檢查或 CI 入口。失敗訊息指明觸發位置、違反的邊界，並引導修正根因、改用推薦路徑。既有違規過多時，先以精確基線攔截新增違規，再依被複製的頻率排序清除既有違規，每清一批就收緊基線。例外限於必要位置，附原因與複查條件。
4. 用正反案例驗收。確認一個已知違規會被阻擋且訊息可操作，一個合法用法仍可通過。若有基線，另外確認新增違規會失敗。回報檢查命令、涵蓋範圍、本次糾正轉成的檢查、已清除與剩餘的既有違規，以及待處理例外。

跨程序引用、框架 API 封裝或抑制註解誤用的做法，見 [約束設計範例](references/constraint-examples.md)。
