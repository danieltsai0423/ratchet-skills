# 功能地圖與執行期證據

## 功能地圖

沿用現有地圖或文件。填補本次驗證所需的條目，名稱使用產品文案、API 資源名稱或 CLI 子命令；同名功能用父層、用途與入口消除歧義。以現有介面核對路徑。以下為條目範例，實際值由目標專案提供。

| 功能名稱 | 入口與前置狀態 | 操作 | 可觀察結果 |
| --- | --- | --- | --- |
| 設定／匯出資料 | 設定頁，載入包含一筆合成記錄的測試帳號 | 選擇 CSV 並確認匯出 | 產生可解析的 CSV，欄名符合契約，且包含該筆記錄 |

## 重跑與取證

- UI 優先用專案的瀏覽器或桌面測試工具。確有需要且環境支援時，可用 Chrome DevTools Protocol 讀取 console、確認網路請求或擷取畫面。API 和 CLI 可直接驗證回傳內容、退出碼與持久化狀態。
- 截圖適合可見終態，影片或 trace 適合操作先後、閃爍或重試。效能主張用條件一致的量測，關鍵操作（啟動、輸入延遲、切換畫面、閒置資源）可保留跨版本基準，確認產量提升時效能沒有退化。狀態圖用來說明路徑，搭配可重跑的轉移測試或模型檢查結果。

## 確認 Agent 理解意圖

實作前或審查時，請 Agent 從使用者視角畫出功能的狀態圖：使用者看到的狀態、觸發轉移的操作，以及錯誤、取消與重試的去向。審查者對照需求檢查狀態是否齊全、轉移是否符合預期，再搭配截圖或影片確認實作與圖一致。圖與需求不符時，先修正理解再修程式碼。
- 同一操作反覆執行且現有入口難以重跑時，可封裝專案 CLI driver。明確提供目標環境、情境與夾具，執行後輸出狀態、可讀錯誤、具語意的退出碼及證據路徑。用一個通過情境與一個可預期失敗情境驗證介面。
