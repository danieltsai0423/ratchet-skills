# 屬性測試與形式驗證

| 方法 | 何時使用 | 交付證據 |
| --- | --- | --- |
| 屬性測試 | 輸入或操作序列多，能描述共同的不變量。例如排序後順序正確且元素多重集合相同，或重試相同操作只造成一次狀態變更。UI 可用現有的屬性測試工具產生合法操作序列。 | 屬性、生成範圍、測試次數、重跑設定，以及失敗時的 seed、框架提供的重播資訊或縮小後反例。 |
| 狀態圖與轉移測試 | 需澄清事件、守衛、轉移順序或不可達狀態。 | 狀態圖及代表路徑的轉移測試。 |
| TLA+ 模型檢查 | 並行、重試、順序或跨端同步具多種交錯。 | 模型、假設、搜尋範圍、已檢查性質及反例軌跡或結果。 |
| Lean 形式證明 | 關鍵演算法可寫成精確定理，且證明成本符合風險。 | 已檢查的定理、假設、證明檔與檢查方式。 |

先寫出可判定的性質，再選生成器、模型或定理。屬性測試刻意包含邊界、重複輸入與適用的空值，並確認生成資料符合前置條件。模型或證明若有抽象，說明哪些實作分支和故障已被納入，以及實作如何對應模型。以代表性反例或負向案例檢查驗證是否能辨識違規，並保留正常入口的實作測試。
